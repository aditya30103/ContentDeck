## What was built

Comprehensive mobile UX overhaul to make ContentDeck feel like a native iOS app rather than a mobile website. Three critical pain points eliminated:

### P0 — Pinch zoom disabled (user's biggest pain)

**Problem:** Unrestrained pinch zoom broke the entire layout — Add button moved off-screen, white spaces appeared at edges, and the app became dysfunctional to use.

**Fixes:**
- `index.html`: Added `user-scalable=no, maximum-scale=1.0, minimum-scale=1.0` to viewport meta
- `src/index.css`: Added `touch-action: manipulation` on `html` — disables double-tap zoom
- `src/App.tsx`: Added `gesturestart`/`gesturechange` event listeners that `preventDefault()` — belt-and-suspenders for iOS Safari which sometimes bypasses viewport meta

### P0 — Overscroll rubber-band eliminated

**Problem:** Pulling past scroll limits revealed the browser's white/grey body background behind the dark app surface.

**Fixes:**
- `src/index.css`: Added `overscroll-behavior: none` on both `html` and `body`
- `src/index.css`: Set theme-aware `background-color` on `html` (light = `surface-50`, `.dark` = `surface-950`), body inherits via `background-color: inherit`

### P1 — 100dvh — address bar reflow fixed

**Problem:** `h-screen` = `height: 100vh` — on iOS Safari, `100vh` includes the address bar, causing content to clip or jump when the bar shows/hides.

**Fixes:**
- `index.html` inline loading spinner: `min-height: 100vh` → `min-height: 100dvh`
- `src/index.css`: `html` and `body` both set to `height: 100dvh; overflow: hidden`
- `src/pages/Dashboard.tsx`: `h-screen` → `h-[100dvh]`
- `src/components/auth/AuthScreen.tsx`: `min-h-screen` → `min-h-[100dvh]`
- `src/components/ui/ErrorBoundary.tsx`: `min-h-screen` → `min-h-[100dvh]`
- `src/components/layout/Sidebar.tsx`: `h-screen` → `h-[100dvh]`
- `src/components/detail/DetailPanel.tsx`: `h-screen` → `h-[100dvh]`

### P1 — MobileHeader slimmed to 3 buttons

**Problem:** 6 buttons (Search, Settings, Stats, Feedback, Theme, Add) overflowed the 390px iPhone 15 header, with Add half off-screen.

**Fix:** `src/components/layout/MobileHeader.tsx` — removed Stats (BarChart3), Feedback (MessageSquare), and Theme toggle. Kept only Search, Settings, Add. All removed actions remain accessible inside the Settings modal. Updated `AppShell.tsx` to stop passing the removed props.

### P1 — Input auto-zoom prevention

**Problem:** iOS zooms into the page when a focused input has `font-size < 16px`.

**Fix:** `src/index.css` — `input, textarea, select { font-size: max(16px, 1rem); }` global rule.

### P1 — AppShell main overscroll

**Fix:** `src/components/layout/AppShell.tsx` — added `overscrollBehavior: 'contain'` to main content area style.

### P2 — HomePage scroll container

**Problem:** `min-h-screen` doesn't create a scroll container — `overflow-y-auto` requires a fixed height to constrain the element.

**Fix:** `src/pages/HomePage.tsx` — `min-h-screen` → `h-[100dvh]`, added `overflow-y-auto` and `overscrollBehavior: 'contain'`.

### P2 — MobileNav label size

**Fix:** `src/components/layout/MobileNav.tsx` — `text-[10px]` → `text-xs` (12px) on all tab labels and counts. Was below WCAG minimum.

### P2 — Input text-sm audit

**Fix:** `src/components/feed/SortSelect.tsx` and `src/components/ui/TagAreaInput.tsx` — `text-sm` → `text-base` on interactive form elements.

## Key decisions

- **`user-scalable=no` is intentional** — This is a personal PWA used exclusively by the owner. Native app feel requires no zoom. WCAG accessibility concern doesn't apply to a single-user personal tool.
- **`gesturestart` listener** — iOS Safari can bypass viewport meta in some versions. The JS listener is belt-and-suspenders and adds ~3 lines.
- **`overscroll-behavior: none` over color-matching** — Eliminating rubber-band entirely (native pattern) vs. just color-matching the bleed. User explicitly chose native app feel.
- **`html { overflow: hidden }` pattern** — Combines with `h-[100dvh]` inner containers to create the "app shell" scroll pattern where body never scrolls; only designated inner containers do.
- **MobileHeader 3 buttons** — Stats and Feedback have been in the header since v3.1 but create overflow. They're still in the Settings modal (accessible on mobile) and the desktop Sidebar (unchanged).
