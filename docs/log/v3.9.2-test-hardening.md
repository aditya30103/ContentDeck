## Key Technical Decisions

**`vi.hoisted()` for mock factories** — `vi.mock` factories are hoisted before `const` declarations. Variables referenced in factory closures must be declared via `vi.hoisted()`. Applied to mockSentry and mockToast in useTagAreas, useTokens.

**`vi.useFakeTimers({ shouldAdvanceTime: true })`** — `waitFor` from RTL uses `setInterval` internally. Plain `vi.useFakeTimers()` freezes these, causing all `useStats` tests to timeout. `shouldAdvanceTime: true` lets real time pass while still controlling `Date` for deterministic boundary tests.

**Optimistic update testing pattern** — For mutations with pending DB (controlled via a hanging Promise): call `mutate()` directly (no `act` wrapper), then `await waitFor(() => ...)` to poll for the optimistic state. TQ's `onMutate` is async and cannot be synchronously awaited.

**Month boundary arithmetic** — `computeStats` uses `setMonth(-1)` for "1 month ago". March 15 → Feb 15. A `doneEntry(30)` (30 days before Mar 15 = Feb 14) falls *outside* this window. Tests use `doneEntry(28)` to stay safely inside.

**`Empty AI response` retry behavior** — `callOpenRouter` catches ALL errors and retries (except AbortError). So `content: null` → "Empty AI response" gets retried 3 times before re-throwing. Tests mock all 3 retries with `mockResolvedValue` (persistent), not `mockResolvedValueOnce`.

**Unhandled rejection suppression** — When a promise rejects between `const promise = fn()` and `await expect(promise).rejects.toThrow()`, Vitest treats it as an unhandled rejection. Add `promise.catch(() => {})` immediately after creation to suppress it while still asserting on the original promise.
