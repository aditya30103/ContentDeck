# v3.10.0 — Reader Mode Overhaul (Phase 1 + Phase 2 partial)

**Date:** 2026-04-17
**Tests:** 481 (+19 new — 10 `useReaderProgress`, 9 ReaderModal reliability)
**Plan:** [reader-mode-overhaul.md](../plan/reader-mode-overhaul.md)
**Motivation:** Reader Mode had not been iterated since v3.0 (2026-02-18). The audit in the plan doc surfaced a lossy pipeline (`article.textContent` stored, rich `article.content` HTML discarded), a heuristic reconstruction layer (`src/lib/reader.ts`) fighting the lossy storage, bot-detecting `User-Agent: ContentDeck/1.0`, no retry, no truncation signal, no resume, and a Read button hidden whenever extraction failed — so users bypassed Reader Mode and clicked the source URL, breaking the Phase 2 Reflect → Review loop.

---

## Phase 1 — Pipeline Rebuild (FULL)

### 1A: Edge function stores sanitized HTML (`supabase/functions/extract-content/index.ts`)
**Change:** Readability is now run inside a linkedom `parseHTML` env. `article.content` is written to `content.html` alongside `content.text`. Conservative allow-list sanitization runs inside the edge function; the client re-sanitizes with DOMPurify for defence-in-depth.
**Fields added:** `content.html`, `content.html_byte_size`.

### 1B: Client renders HTML via `.prose` (`src/components/reader/ReaderModal.tsx`)
**Change:** Replaced the block-render heuristic path with a single `<div dangerouslySetInnerHTML />` inside `.prose prose-sm|base|lg dark:prose-invert`, DOMPurify-sanitized on the client. Fallback to plain-text rendering when `content.html` is absent (graceful degradation — no backfill required for old bookmarks).

### 1C: Heuristic parser deleted
**Removed:** `src/lib/reader.ts` and `src/lib/__tests__/reader.test.ts`. The reconstruction layer is no longer reachable; `@tailwindcss/typography` handles typography, DOMPurify handles sanitization.

### 1D: Dependencies
**Added:** `@tailwindcss/typography`, `dompurify`, `@types/dompurify`. Typography plugin registered in `src/index.css`.

## Phase 2 — Reliability (PARTIAL: 2A, 2D, 2E, 2F)

### 2A: Safari UA + retry/backoff (`supabase/functions/extract-content/index.ts`)
**Change:** Edge function UA switched to a realistic macOS Safari 17.6 string. On `429 | 500 | 502 | 503 | 504`, the fetcher retries twice with exponential backoff (1 s, 3 s), respecting a `Retry-After` header if present. `403` does not retry (no fallback chain yet — deferred to 2B).

### 2D: Raise truncation cap + UI signal (`supabase/functions/extract-content/index.ts`, `src/types/index.ts`, `src/components/reader/ReaderModal.tsx`)
**Change:** `TEXT_CAP` and `HTML_CAP` raised from 100 KB → 500 KB. New `content.truncated: boolean` field set when either cap is hit. Reader footer renders "Truncated at the 500 KB cap — [Open original]" notice when `truncated === true`.

### 2E: Failed / partial reader states (`src/components/reader/ReaderModal.tsx`, `src/components/detail/DetailPanel.tsx`, `src/pages/Dashboard.tsx`, `src/hooks/useBookmarks.ts`, `src/types/index.ts`)
**Change:**
- `ContentStatus` extended with `'partial'`; `BookmarkContent.method` extended with `'postlight' | 'microlink' | 'partial'`.
- Read button now always shows when `bookmark.url` exists (not a sentinel `book://`), disabled only while `extracting`. No more silently hidden affordance.
- On open with `content_status === 'failed' | 'skipped'`: Reader renders an empty state with **Retry** + **Open original in browser**.
- On open with `content_status === 'partial'`: Reader renders the excerpt with a "Could not extract full article" banner.
- New `retryExtraction(bookmark)` function on `useBookmarks`. Optimistic `extracting` state + rollback on error + Sentry + toast.

### 2F: Reading-progress persistence (`src/hooks/useReaderProgress.ts` — new, `src/components/reader/ReaderModal.tsx`)
**Change:** New `useReaderProgress(bookmarkId)` hook — throttled localStorage writes (250 ms window, leading edge + trailing flush, unmount flush). Exports `RESUME_THRESHOLD = 0.05`. Returns `{ savedProgress, write, clear }`.

In ReaderModal: sticky "Resume from X%" pill at top of Reader when `savedProgress > RESUME_THRESHOLD`. Scroll handler writes progress. On `bookmark.status === 'done'`, progress is cleared automatically.

### Latent bug fixed during Phase 2
Inside `extract-content`, `const html = await response.text()` collided with the later `const html` for the sanitized output. Would have thrown a Deno `SyntaxError` on first run. Fixed by renaming the outer binding to `rawHtml`.

## What did not ship (deferred)

- **2B Fallback chain** — `@postlight/parser` and Microlink Article API as Readability fallbacks. Both need Deno-compat verification via the esm.sh import path before touching the extractor.
- **2C PDF extraction** — content-type sniff → `pdfjs-dist` (Mozilla; verify Deno compat or fall back to `pdf-parse`). Add `content.page_count` + `content.pdf_source`.
- **Phase 3 Value Unlock** — AI summary card, highlights, TOC, YouTube transcript UX. Independently shippable once 2B + 2C land.
