## DB Schema

```sql
create table feedback (
  id                  uuid primary key default gen_random_uuid(),
  user_id             uuid not null references auth.users(id) on delete cascade,
  feedback_type       text not null check (feedback_type in ('bug', 'suggestion', 'other')),
  title               text not null,
  description         text,
  severity            text check (severity in ('blocking', 'major', 'minor', 'polish')) default 'minor',
  app_context         jsonb not null default '{}'::jsonb,
  system_context      jsonb not null default '{}'::jsonb,
  active_bookmark_id  uuid references bookmarks(id) on delete set null,
  status              text not null default 'open'
                        check (status in ('open', 'investigating', 'resolved', 'wont_fix')),
  resolution_note     text,
  created_at          timestamptz default now(),
  updated_at          timestamptz default now()
);
```

Reuses existing `set_user_id()` trigger. `active_bookmark_id` uses `on delete set null` — deleted bookmarks don't orphan feedback. RLS: `auth.uid() = user_id`.

## Key Decisions

### Context snapshot at open time
`useEffect` fires once when `open` transitions to `true`. Reads all UI state from `useUI()` + `activeBookmark` prop at that moment. Suppressed `react-hooks/exhaustive-deps` with comment — same pattern as the metadata enrichment effect in Dashboard.tsx. If the user opens another bookmark before the modal finishes opening, the context should still reflect the bookmark that triggered the feedback.

### No `.select().single()` on insert
The `submitFeedback` mutation uses plain `insert()` (no returned data) + `invalidateQueries` in `onSuccess`. This avoids the `@typescript-eslint/no-unsafe-assignment` lint error that fires when destructuring `data: any` from Supabase's insert response. The re-fetch after invalidation serves the same purpose.

### `severity` for non-bug types
DB stores `'minor'` for suggestion/other (constraint allows it; UI hides the field). This keeps the schema uniform without nullable complexity.

### Mock Supabase safety
`feedback` added to `TableName` union and `TableStore` in `mock-supabase.ts`. The generic `MockQueryBuilder` handles it without any special-casing — all CRUD operations work in demo mode.

### Test mock pattern
The mock builder shares `_resolve` across ALL operations (select/insert/update). Tests set `_resolve` to the array the *re-fetch* should return (not just what the mutation returns), so that `invalidateQueries` re-fetches correctly in the test environment.

## Triage Workflow (New)

**Before:** Remember issue → open user-feedback.md → write it down manually.

**After:** See issue → click Feedback (sidebar/mobile) → type title → submit (~15s).

**Review:** Settings → Feedback tab → filter Open → work top-to-bottom. Each item has full `app_context` + `system_context` for reproduction.
