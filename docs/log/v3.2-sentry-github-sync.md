# v3.2 — Sentry Error Tracking + GitHub Issues Sync

**Issues:** #21 (Sentry) + #22 (GitHub Issues sync)
**Branch:** `feat/21-22-sentry-github-issues-sync`
**Date:** 2026-02-25

---

## What was built

### Sentry Error Tracking (#21)

Zero production error visibility → automatic capture with full stack traces.

- **`@sentry/react`** + **`@sentry/vite-plugin`** installed
- **`vite.config.ts`**: `build.sourcemap: true` + conditional `sentryVitePlugin` (only when `SENTRY_AUTH_TOKEN` is set in CI)
- **`src/main.tsx`**: `Sentry.init()` before `createRoot` — DSN from `VITE_SENTRY_DSN` env var, no-op when DSN is absent
- **`ErrorBoundary.tsx`**: `Sentry.captureException()` in `componentDidCatch` with `componentStack` context
- **`.env.local`**: `VITE_SENTRY_DSN=` placeholder added
- **`.github/workflows/ci.yml`**: `VITE_SENTRY_DSN` injected from GitHub Secrets

### GitHub Issues Sync (#22)

Feedback submissions now automatically create linked GitHub Issues.

- **SQL migration** (`sql/20260225_github_issue_tracking.sql`): two new nullable columns on `feedback` table — `github_issue_number INTEGER`, `github_issue_url TEXT`
- **`FeedbackItem` type** extended with `github_issue_number?` + `github_issue_url?`
- **`supabase/functions/create-github-issue/index.ts`**: new edge function
  - JWT-verified (user-scoped client for ownership check, admin client for write-back)
  - Fetches feedback row via RLS, builds markdown issue body, POSTs to GitHub API
  - Updates feedback row with `github_issue_number` + `github_issue_url` on success
  - Returns 502 on GitHub API error (non-critical — feedback already saved)
- **`useFeedback.ts`**: `mutationFn` updated to `.select('id').single()` after insert, then non-blocking `functions.invoke('create-github-issue')` — failure silently swallowed
- **`FeedbackList.tsx`**: GitHub badge (`GitBranch` icon + `#N`) per card, links to the issue

### Tests

- `useFeedback.test.ts`: `functions.invoke` spy added to mock, `SAMPLE_FEEDBACK` fixture updated with nullable GH fields, 2 new tests:
  - "calls create-github-issue with feedback_id after successful submit"
  - "succeeds and shows toast even if GH sync errors"

## Key decisions

- **No-op when DSN absent**: `enabled: !!import.meta.env.VITE_SENTRY_DSN` — dev builds without DSN don't send events
- **GH sync is non-critical**: feedback is already persisted before the edge function fires; any GitHub API failure is silently swallowed client-side
- **No labels**: label creation requires extra API calls; labels can be managed manually in GitHub
- **JWT auth pattern**: follows `extract-content` — user-scoped client for ownership, admin client for write-back
- **SW cache bump**: `contentdeck-v3.0.9` → `contentdeck-v3.1.0` (no SW behaviour change, but new deployment warrants a bump)

## v3.2.1 — Full Sentry Coverage (#25)

**Branch:** `feat/25-sentry-full-coverage` | **PR:** #26 | **Date:** 2026-02-25

### What was added

The initial Sentry integration only captured render errors (ErrorBoundary) and the `onError` callbacks already existed in `useFeedback`. This pass extended coverage to every failure path in the app.

- **`src/main.tsx`**: global `unhandledrejection` listener — catches promise rejections that Sentry's auto-capture misses in some browsers
- **`src/hooks/useBookmarks.ts`**: `Sentry.captureException(err)` in all 10 mutation `onError` callbacks; `.catch()` added to the `autoFetchMetadataAndTag → triggerExtraction` fire-and-forget chain
- **`src/hooks/useTagAreas.ts`**: captureException in 4 mutations; `createArea` skips capture for expected client-side duplicate errors (`err.message.includes('already exists')`)
- **`src/hooks/useTokens.ts`**: captureException in `createToken` + `deleteToken`
- **`src/hooks/useFeedback.ts`**: captureException in `submitFeedback` + `updateFeedbackStatus`
- **`src/hooks/useAuth.ts`**: `.catch()` on `getSession` fire-and-forget — sets `loading: false` and captures to Sentry
- **`supabase/functions/save-bookmark/index.ts`**: structured `console.error` with context (url, userId, error) for token lookup failure and insert failure
- **`supabase/functions/extract-content/index.ts`**: structured `console.error` for auth failure, bookmark not found, ownership mismatch, extraction failure

### Key decisions

- **Edge functions use `console.error`, not Sentry SDK**: Deno runtime can't use the browser Sentry SDK; logs appear in Supabase function logs dashboard
- **Duplicate area error is not a bug**: expected validation path — intentionally excluded from Sentry to keep noise low
- **No new tests**: coverage additions are wiring changes in `onError`/`.catch()` — existing 165 tests still pass
