## What Shipped

### 2.1 — Values Onboarding (`ValuesOnboardingModal`)

**The problem it solves:** The scoring engine needs to know the user's reading constitution — which areas they care about, how long their sessions are, and what they want less of — before it can make good recommendations. Without this, it falls back to pure signal-based scoring, which is less personal.

**What it is:** A one-time, three-step modal shown on first visit to `/`. It never re-appears unless reset from Settings. It is opt-skippable at any step — skipping leaves `contentdeck_values` unset and the scoring engine operates without personalization.

**Three questions:**
1. **Priority areas** — multi-select from the user's existing tag areas. Uses the colored area chips with `ring-2 ring-primary-500 scale-105` on selection. Areas with no tags yet prompt the user to set up areas in the library first.
2. **Session length** — single-select from Quick (≤15 min), Medium (~30 min), Deep (1h+). Rendered as a 3-col grid with large emoji, label, and sublabel. Default is Medium.
3. **Suppressed areas** — optional multi-select from same area list; priority areas are disabled (can't be both priority and suppressed). Uses `ring-2 ring-red-400` for visual contrast. "Skip" button is available.

**Storage:** `localStorage` key `contentdeck_values`. Serialised as:
```typescript
interface UserValues {
  priorityAreaIds: string[];    // area UUIDs the user cares about most
  sessionLength: 'quick' | 'medium' | 'deep';
  suppressedAreaIds: string[];  // areas the user wants less of
  completedAt: string;          // ISO timestamp
  version: 1;
}
```
No new DB table. The values are personal and device-local — they represent a stated intent in the moment, not a permanent profile. A future sync migration is straightforward if needed.

**Reset:** SettingsModal → Personalization section → "Reset values" button calls `clearUserValues()` and fires a `storage` event so the `useUserValues` hook syncs across tabs.

**Hook:** `useUserValues()` returns `{ values, setValues, clearValues }`. It listens on the `storage` event so the home screen updates if another tab changes the values.

### 2.2 — Scoring Engine (`src/lib/scoring.ts`)

**The problem it solves:** A growing queue of saved bookmarks is useless if you spend mental energy deciding what to read. The scoring engine makes one confident recommendation per session so the user doesn't have to choose.

**Design constraint:** The engine must be interpretable. Every recommendation carries a plain-English reason derived from the dominant score term. The reason is fully deterministic — not generated by AI, not random. It is the human-readable rendering of whichever component contributed most to the score.

#### Score formula

```
score(bookmark, context) =
  staleness_score       × w1
  + diversity_bonus     × w2
  + effort_match        × w3
  + completion_affinity × w4
  + topic_freshness     × w5
  + favorites_bonus     × w6
  − recency_penalty     × w7
```

#### Weight vectors (5 mood modes)

| Mode | w1 staleness | w2 diversity | w3 effort | w4 completion | w5 freshness | w6 favorites | w7 recency |
|------|-------------|-------------|----------|--------------|-------------|-------------|-----------|
| `default` | 0.25 | 0.20 | 0.20 | 0.15 | 0.10 | 0.05 | 0.05 |
| `deep-dive` | 0.20 | 0.10 | **0.35** | 0.20 | 0.10 | 0.05 | **0.00** |
| `light-read` | **0.30** | 0.15 | 0.25 | 0.15 | 0.05 | 0.05 | 0.05 |
| `quick-win` | **0.35** | 0.15 | 0.15 | 0.20 | 0.05 | 0.05 | 0.05 |
| `shuffle` | **0.05** | **0.60** | 0.10 | 0.05 | 0.10 | **0.00** | 0.10 |

`deep-dive` turns off the recency penalty entirely (zero weight) — you should re-read something you're in the middle of if it's a deep topic. `shuffle` dominates with diversity (0.60) and ignores staleness and favorites.

#### Time-of-day adjustments (default mood only)

Applied on top of the `default` weight vector before scoring:
- **Morning:** effort +0.05, staleness −0.05 (prioritise focused/longer reads when fresh)
- **Evening:** effort −0.05, staleness +0.05 (de-prioritise long reads, lean towards clearing backlog)
- **Weekend:** effort +0.05, recency penalty −0.05 (unlock longer content; less penalty for re-visiting)

#### Score components in detail

**Staleness** (`scoreStaleness`): `min(1, daysInQueue / (2 × medianQueueDays))`. Uses the median queue days for the same source type — an article waiting 10 days against a median of 5 days scores 1.0, but a book at 10 days against a 60-day median scores 0.08. Prevents books from always dominating just because they're old.

**Diversity** (`scoreDiversity`): `max(0, 1 − maxRecentCount / 3)` where `maxRecentCount` is how many of the last 7 finished items shared an area with this bookmark. If the user just finished 3 AI articles, another AI article gets diversity ≈ 0. Suppressed areas get a hard cap of 0.05. Priority areas get +0.2 boost (capped at 1.0).

**Effort match** (`scoreEffort`): Gaussian bell curve centred on `targetMinutes`. `exp(−(minutes − target)² / (2σ²))`. Target is derived from UserValues `sessionLength` (quick→8 min, medium→25 min, deep→60 min), then scaled by time slot (evening ×0.7, morning ×1.2, weekend ×1.4). Sigma is 15 min normally, 30 min for deep-dive mode. Falls back to source-type proxies when reading time is unknown (book=60, arXiv=45, YouTube=15, blog=12, substack=20, LinkedIn=5, Twitter=2).

**Completion affinity** (`scoreCompletion`): The historical finish rate for this source type — how often the user completes items of this type. Computed from the full bookmark history. Floored at 0.1 so no source type scores zero. If the user finishes 80% of articles but only 20% of books, the engine prefers articles.

**Topic freshness** (`scoreFreshness`): Momentum bonus — if the user has been on a roll with an area recently (1 recent done item → 0.5, 2 → 0.8, 3+ → 1.0), they likely want to continue. Items with no areas get 0.3 (neutral). No recent activity in the area returns 0.0.

**Favorites** (`scoreFavorites`): Binary. 0 or 1. Starred bookmarks get a small but consistent lift regardless of other factors.

**Recency penalty** (`scoreRecencyPenalty`): Penalises items recently started but not finished. Linear decay: items opened in the last 48 hours score up to 1.0 penalty (recently abandoned = avoid recommending again immediately). Items older than 48h get zero penalty.

#### Reading time extraction (4-level fallback)

`getReadingMinutes(bookmark)` tries in order:
1. `content.reading_time` (from Readability extraction)
2. `metadata.reading_time` (from YouTube Data API or Microlink)
3. `metadata.duration` parsed as `H:MM:SS` or `MM:SS` → minutes
4. `(content.word_count ?? metadata.word_count) / 200` (200 wpm reading speed)

Returns `null` if all fail — the effort scorer then falls back to source-type proxies.

#### Reason strings (interpretable output)

| Dominant factor | Example reason |
|----------------|---------------|
| `staleness` | "This has been waiting 21 days — longer than most in your queue." |
| `diversity` | "You've been reading a lot of AI Research. Here's something different." |
| `effort` | "12-min read — fits your session." |
| `completion` | "You almost always finish blog content." |
| `freshness` | "You've been on a roll with Product — keep the momentum." |
| `favorites` | "You marked this as a favourite." |

The dominant factor is whichever component contributes the most weighted score (`component × weight`).

#### `buildScoreContext` — what it computes

Called once per render via `useMemo`. Inputs: full bookmark array, UserValues, mood, current Date. Outputs: the `ScoreContext` object which includes:
- Last 7 finished bookmarks sorted by `finished_at` descending
- Area frequency map across those 7 (for diversity scoring)
- Completion rates per source type (floored at 0.1)
- Median queue days per source type (for staleness normalisation)
- Time slot, hour, day of week, weekend flag
- Final weight vector after time-of-day adjustments

#### `rankBookmarks` — entry point

```typescript
rankBookmarks(bookmarks, ctx, { statusFilter?, hardMaxMinutes? }): ScoreResult[]
```

- Filters by status (default: `['unread']`)
- If `hardMaxMinutes` set, drops items with known reading time exceeding the limit (unknowns pass through charitably)
- Scores all candidates, sorts descending by `totalScore`

#### Tests: `src/lib/__tests__/scoring.test.ts` (27 tests)

- `getReadingMinutes` priority order — all 4 fallback levels tested
- `buildScoreContext` — completion rates floor at 0.1, recentDone filtering
- Staleness — older item ranks above newer (all else equal)
- Diversity — underrepresented area beats saturated area; priority boost; suppression hard-caps at ≤0.05
- Effort — item near target beats far items; mood-specific targets verified
- Quick-win hard filter — items >15 min excluded; unknown reading time passes through
- Shuffle mode — diversity-dominated (w2=0.6), fresh area beats stale
- Recency penalty — recently touched items score lower; >48h has zero penalty
- Favorites — starred item scores higher than identical unstarred item
- Empty bookmark array — no errors, returns empty array

### 2.3 — New Home Screen (`src/pages/HomePage.tsx`)

**The paradigm shift:** The library is no longer the front door. The home screen is a curator that makes a single confident recommendation rather than presenting a queue to scroll through. The user's job is to confirm or override, not to decide from scratch.

**Route:** `/` → `HomePage`. Library moves to `/library`. Both routes defined in `App.tsx` via react-router-dom v7. Catchall `*` redirects to `/`. Demo mode stays on `/library` — the home screen requires real data to be meaningful.

**Layout (max-w-lg mx-auto — intentionally narrow):**

```
🌙 Good evening, Aditya          [⚙]
   9:14 PM

┌──────────────────────────────────────┐
║ TONIGHT'S PICK                       ║  ← context label (mood/time aware)
║                                      ║
║ [Thumbnail]  Title of article        ║
║              [Blog] · 12 min         ║
║                                      ║
║ "Waited 21 days — longer than most." ║  ← reason (italic, deterministic)
║                                      ║
║ [ Start reading →  ]    [↗]          ║  ← primary CTA + open tab
└──────────────────────────────────────┘

┌────────────────┐  ┌────────────────┐
│ ▶ Continue     │  │ ⚡ Quick Win   │  ← secondary slots (only if non-null)
│ Article title  │  │ Article title  │
│ Blog · 8 min   │  │ Blog · 6 min   │
└────────────────┘  └────────────────┘

Mood
[🧠 Smart] [🔥 Deep] [📖 Light] [⚡ Quick] [🎲 Shuffle]

Browse Library →                   Sign out
```

**Components (all local to the file):**

`HomeHeader` — displays time-of-day emoji + greeting string + user's first name extracted from email (e.g. `aditya.arya@...` → `Aditya`). Live clock updates every 60s via `setInterval` in a `useEffect`. Settings gear button opens `SettingsModal`.

`PrimaryPickCard` — the hero recommendation. Left edge has a 4px source accent bar using `--color-source-*` CSS variables (inline `backgroundColor` style — no Tailwind class needed since the color is dynamic per source type). Context label changes based on mood and time of day (`"TONIGHT'S PICK"` / `"DEEP DIVE PICK"` etc.). Shows optional thumbnail if available. Reason text in italics. Two CTAs: "Start reading →" (marks unread → reading, opens URL) and `↗` ghost icon (open in new tab without changing status). Full loading skeleton with `animate-pulse`. Empty state if `topPick` is null.

`SecondaryCard` — used for both Continue (amber, `PlayCircle` icon) and Quick Win (indigo, `Zap` icon) slots. `role="button"` + `tabIndex={0}` + keyboard handler for Enter/Space. The row (`grid grid-cols-2`) only renders if at least one slot is non-null — avoids a ghost grid with two empty divs.

`MoodSelector` — horizontal scrolling row of 5 pill buttons. `aria-pressed` on each. Active state: `bg-primary-600 text-white`. Scroll container has `scrollbarWidth: none` (CSS property, no Tailwind equivalent). `min-h-[36px]` — intentionally smaller than the standard 44px touch target since these are filter toggles, not primary actions.

`HomeFooter` — "Browse Library →" Link to `/library` and Sign out button. Sign out button hidden in demo mode.

**Philosophy compliance:**
- The unread count is **never shown** on this screen. The queue is invisible by design. Showing the pile would shift the user from intentional reading to inbox-clearing anxiety.
- One primary pick. Two supplementary slots. The screen commits to something — the user's job is to confirm or override via mood selector.
- "Start reading" is the dominant CTA. Its size and position communicate that the right next action is to begin, not to browse.
- Reason text makes the engine transparent. The user understands *why* this item was chosen without needing to trust a black box.

## Key Decisions

### Pure client-side engine, no new infrastructure
All scoring runs over the TanStack Query bookmark cache (`useBookmarks`). No edge functions, no DB queries during recommendation. The cache already has everything needed: `created_at`, `source_type`, `status`, `is_favorited`, `areas`, `metadata.reading_time`, `started_reading_at`, `finished_at`. Total cost: zero.

### Reason strings are deterministic, not AI-generated
The dominant factor is computed mathematically (`component × weight` for each of 6 factors; highest wins). The reason string is a lookup from a `REASONS` record keyed by `DominantFactor`. This is a deliberate product decision: the user should be able to *understand and predict* why they got a recommendation. An AI-generated reason would be more fluent but less trustworthy.

### localStorage for UserValues (no DB table yet)
Values are personal and device-local for v1. They represent the user's stated preferences in the moment, not a permanent server-side profile. Cross-device sync can be added later by persisting to a `user_settings` table. The key is `contentdeck_values`; the format is versioned (`version: 1`).

### No unread count on the home screen
The queue size is intentionally hidden. This is the core philosophy constraint: ContentDeck should feel like a peaceful reading practice, not an inbox to triage. Showing a count of 47 unread items would shift the user's mental model from "what should I read next" to "how do I clear this list."

### `max-w-lg` narrow layout — not a dashboard
The home screen is not the library. It doesn't need wide columns, filter bars, or view toggles. A single centered column (`max-w-lg mx-auto`) works on all screen sizes and reinforces the curator framing. Mobile and desktop render identically.

### Source accent bar via CSS variable inline style
The left border color is dynamic per source type and uses CSS variables already defined in `src/index.css` (`--color-source-youtube`, etc.). These can't be used as Tailwind utilities directly without SafeList configuration, so `style={{ backgroundColor: 'var(--color-source-*)' }}` is the correct approach. The color is 4px wide (`w-1`) — visible enough to be informative, narrow enough not to compete with content.
