## What Shipped

### 2.1 — Values Onboarding

Three-question, one-time onboarding modal surfaced on first visit to the home screen. Collects the user's stated reading constitution:

1. Which tag areas matter most (multi-select)
2. Typical session length — Quick (≤15 min) / Medium (30 min) / Deep (1h+)
3. Topics to see less of (optional suppression, multi-select)

Stored in `localStorage` under key `contentdeck_values`. No new DB table. Reset button added to SettingsModal.

### 2.2 — Scoring Engine

Pure client-side scoring engine — zero infrastructure cost, fully testable.

**7-component formula:**
```
score(b, ctx) =
  staleness_score        × w1  (days in queue ÷ source-type median)
  + diversity_bonus      × w2  (underrepresented area vs recent 7 done items)
  + effort_match         × w3  (reading_time Gaussian centred on session target)
  + completion_affinity  × w4  (finish-rate for this source type)
  + topic_freshness      × w5  (recent done items in same area → momentum)
  + favorites_bonus      × w6  (is_favorited fixed bonus)
  - recency_penalty      × w7  (penalise items viewed in last 48h)
```

**5 mood weight vectors:** `default` · `deep-dive` · `light-read` · `quick-win` · `shuffle`

**Interpretability:** every recommendation includes a plain-English `reason` string derived from the dominant score factor. Not AI-generated — deterministic rendering of the top term.

**27 unit tests** in `src/lib/__tests__/scoring.test.ts`.

### 2.3 — New Home Screen UI

Full curator home screen replacing the `/` route stub. Paradigm inversion: one primary recommendation, not a menu.

**Layout (max-w-lg mx-auto):**
- `HomeHeader` — time-of-day greeting + live clock + settings gear
- `PrimaryPickCard` — hero card with source accent bar, reason, "Start reading" + open-in-tab CTAs, loading skeleton, empty state
- `SecondaryCardsRow` — 2-col grid (Continue + Quick Win), only rendered when at least one slot is filled
- `MoodSelector` — 5 pill buttons (Smart / Deep / Light / Quick / Shuffle), `aria-pressed`
- `HomeFooter` — "Browse Library →" link + Sign out button

**Philosophy compliance:**
- Unread count is never shown (the pile is invisible by design)
- One primary pick — the system commits; the user confirms or overrides
- "Start reading" is the dominant CTA, not a browse button
- Reason text shows WHY the engine chose — interpretable, not opaque

## Key Decisions

### Pure client-side scoring engine
All scoring logic runs over the TanStack Query bookmark cache. No new edge functions, no DB queries during recommendation. The cache already has everything needed: `created_at`, `status`, `source_type`, `is_favorited`, `areas`, `metadata.reading_time`.

### localStorage for UserValues
No new DB table for v1. Values are personal and device-local — they represent the user's stated reading constitution in the moment. A future sync migration is straightforward if needed.

### react-router-dom v7
Added to support the `/` → `/library` route split. `BrowserRouter` in `main.tsx`. Routes defined in `App.tsx`. Demo mode stays on `/library` only.

### `max-w-lg` narrow layout
The home screen is intentionally not a wide dashboard. `max-w-lg mx-auto` — curator-first, single column. Mobile and desktop share identical layout.

### No unread count on home screen
The queue size is intentionally hidden. Showing the pile triggers anxiety and encourages queue-draining behaviour. The curator picks one thing; the pile stays invisible.

### Source accent bar
4px left border on the primary pick card uses the source type's CSS variable (`--color-source-*`). Instant visual signal without repeating the badge.
