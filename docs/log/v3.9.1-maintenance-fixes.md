**Date:** 2026-03-30

## Summary

Two production bug fixes identified via Sentry (CONTENTDECK-3) and GitHub issue #52.

---

## Fix — Supabase PostgrestError bypassing Sentry filter (PR #57, CONTENTDECK-3)

**Root cause:** `createArea.onError` in `src/hooks/useTagAreas.ts` filtered duplicate-area errors with `err instanceof Error && err.message.includes('already exists')`. Supabase `PostgrestError` objects are plain `{ code, details, hint, message }` — not `Error` instances — so the check always failed and every 409 unique-violation was reported to Sentry.

**Changes:**
- `src/hooks/useTagAreas.ts` — added Postgres error code `'23505'` check via safe `unknown` cast alongside the existing `instanceof Error` guard.

---

## Fix — arXiv metadata fetch broken by CORS (PR #58, closes #52)

**Root cause:** `fetchArxivMetadata` in `src/lib/metadata.ts` called `https://export.arxiv.org/api/query` directly from the browser. `export.arxiv.org` returns no `Access-Control-Allow-Origin` header, blocking all browser requests. arXiv metadata (title, authors, abstract) has been silently broken in production since v3.3.

**Fix:** New `fetch-arxiv-metadata` Supabase Edge Function proxies the arXiv Atom API server-side (no CORS restriction), parses the XML, and returns structured JSON. `fetchArxivMetadata()` now calls `supabase.functions.invoke('fetch-arxiv-metadata', { body: { id } })` instead of fetching directly.

**Deploy step (one-time, post-merge):**
```
npx supabase functions deploy fetch-arxiv-metadata --no-verify-jwt
```

**Changes:**
- `supabase/functions/fetch-arxiv-metadata/index.ts` — new Edge Function (CORS headers, arXiv ID validation, Atom XML parsing, structured JSON response)
- `src/lib/metadata.ts` — `fetchArxivMetadata` replaced with Edge Function invocation; removed `DOMParser` XML parsing from client
- `src/lib/__tests__/metadata.test.ts` — arXiv tests rewritten to mock `supabase.functions.invoke` via `vi.hoisted()`; added routing test confirming `fetch` is never called for arXiv

**Key learnings:**
- `vi.hoisted()` is required when a mock factory references variables declared outside the factory — `vi.mock` is hoisted before `const` declarations, causing "Cannot access before initialization"
- Worktree directories don't inherit `.env.local` — copy it in for tests that need real env vars
